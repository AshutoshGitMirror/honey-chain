How the chain works, plain
hash = SHA256(prev_hash + beekeeper_id + hive_id + harvest_date + flower)
Each new block stores prev_hash. If anyone changes the village or flower, the hash breaks. New data is a new block with prev_hash, never an edit.

Flexible: if we pool many households for one plant run, the plant lot lists many field hashes. Label is written after the lab, not before. Household pin is everywhere, same coords for customer and KVIC.

Rating without gaming: Old way was device ID, easy to game with many machines. New way: QR holds hash plus a one time token. When you scan a valid QR, the server gives a single use JWT. You can rate only with that JWT. No valid scan, no rating. You cannot spam from other machines. If you scan again, you do not get a second token for the same batch. Blockchain way is the same idea: the rating is a transaction that must be signed by the holder of the token.
