Honey Chain — how data moves

One harvest, one hash at the farm. After that we add notes that link to the first hash. No one rewrites it. The hash is a fingerprint, prev_hash links to the last harvest.

How the chain works, plain
hash = SHA256(prev_hash + beekeeper_id + hive_id + harvest_date + flower)
Each new block stores prev_hash. If anyone changes the village or flower, the hash breaks. New data is a new block with prev_hash, never an edit.

Real: 13,099 beekeepers on MadhuKranti 2021, FPO bulk upload, Api Care Sikkim prints QR per jar, Atulaya Haryana 200k boxes to Ramnagar, Honavar Co-op 1941 has plant. Coop not farmer prints. Pooling by coop at plant is how 300 kg runs are filled.

Rating without gaming: Old way was device ID, easy to game. New way: QR holds hash plus a one time scan token. When you scan a valid QR, the server gives a single use token. You can rate only with that token. One QR, one rating. Blockchain way is the same idea: the rating is a transaction signed by the holder of the token.
